Before two result-preserving caches (each cat's most likely state per step for `nearCat`; one
decision per state that differs only in steps left) the spec start took 40 s.

The budget is a projection from 12:00 (104 steps) in 100 ms, with up to 3 × 2^`maxLinks` = 12
cases: about 1 ms per case-step. With the spec's knobs one case-step costs 66 ms; with the most
aggressive knobs above, 7 ms. Where the time goes (profile): the decision function per distinct
state (gates, scores, place options), building and sorting state keys in `normalise`, and
`starts` (place options, paths, duration splits): about 30 µs per state per step.

Since 2026-11-22 (lantern edge, re-run) this budget case is gone: `07` §4 now measures a re-run
with Marti live and the other cats in the fog, streamed. The numbers above (every cat fogged)
still describe the whole-day projection used by vetting and calibration; the re-run is to be
measured.

## Item 0: hysteresis, boredom, the decision cache — done 2026-11-22

`feat: hysteresis decisions, boredom and the shared decision cache…` (pack install of 2026-11-22,
`03` §8.2, §13.3; M2-6 two keys). **Golden files changed once**, with `npm run golden:update`:

reference on Rokko, the shop and the crew.

Whole-day projection, seed 1, every cat fogged (`scripts/fog-bench.ts`):

| knobs | before (step 4) | now | most states | decisions computed | from the cache |
| --- | --- | --- | --- | --- | --- |
| coarse (minStatePpm 20 000, 2 bands) | 21.9 s | 3.2 s | 203 | 5 686 | 58 701 (91%) |
| spec (100, 4 bands) | — | 71.5 s | 3 002 | 66 175 | 2 021 496 (97%) |

At the spec knobs nearly all mass is "changed" every step: boredom rises every tick, so a
fraction of every state moves a band each step, and that fraction must decide. The decisions
themselves are cheap now (97% from the cache); building each cache key (leaf values, place
options) is what costs. Next candidates, all result-preserving: leaf values cached per case and
step, cache keys reused for repeated states within a step, integer-coded states.
