# M1 — Engine: one history: handoff

Branch `m1-one-history` (from `m0-scaffold`). Session date 2026-11-21.

## What was built

- **Content.** `src/content/schemas/dsl.ts` holds the content language: conditions, score terms,
  storylet effects, card primitives. `schemas/chapter.ts` has one schema per Chapter 1 file.
  `content/check.ts` ports `docs/reference/ch1-slice-validate.mjs` onto the parsed content.
  `load.ts` (`loadChapter`) parses, cross-checks, applies the cast mode (`full`/`core`), derives
  lookups and freezes the result. Every problem is reported in one `ContentError`.
  `npm run content:check` now validates `ch1/`: 0 errors, and the same warnings as the slice's
  validator ("event emitted but nothing reacts").
- **Simulation**, `src/sim/`, following `03` §1–§12:

  | File | What it does |
  | --- | --- |
  | `space.ts` | clock, positions, Dijkstra with tie-break, `via` / `edgesTagged` |
  | `perception.ts` | `perceives` |
  | `conditions.ts` | every condition kind |
  | `scores.ts` | score terms and hazard rates |
  | `effects.ts` | storylet effects |
  | `pins.ts` | validity, pending pins, specials, every primitive, pressure, `touchedBy` |
  | `cats.ts` | hooks, mods, voices, bodies, place selectors, free decisions, control |
  | `storylets.ts` | activation, roles, auto/hazard/choice exits as branch points |
  | `sifting.ts` | detector pools |
  | `step.ts` | the eight phases, weather, perception, anchor |
  | `history.ts` | initial state per stream, `runHistory` |

- **CLI.** `npm run sim -- --seed 1 [--stream n] [--pins f.json] [--content dir] [--from] [--to] [--cat]`
  prints one line per event (`tick HH:MM type details`), then the end and the final hash.
  (In PowerShell, `npm run sim -- …` loses the `--`; use `npx tsx src/cli/sim.ts --seed 1`.)
- **Tiny world**, in `tests/fixtures/tiny/`, generated by `make.ts`. It loads through the real
  loader. It has six places (one closable edge, one indoor space with a window) and three cats
  (hero with willpower 850). It covers every exit and role kind, two detectors, every card
  primitive, one power with `attract` and one with `collapse`.
- **The app and the worker** both load and cross-check Chapter 1 at startup (`02` §5).

## Deviations and decisions

- The twelve planned schema files became one `chapter.ts` with a section per file
  (`docs/decisions.md`).
- One state field beyond `03` §5: `echoes`, for socialSpread hops next tick. A few extra event
  types for traces. A terminal storylet state stays in `state`. All listed in
  `docs/decisions.md`.
- **Performance work done:**
  - an explicit path memo: 6× faster, same hashes;
  - removing a redundant path check;
  - computing open-choice actors once per tick;
  - a typed `cloneState`, tested equal to a JSON round-trip.

  One Chapter 1 history went from 1.5 s to about 120 ms.

## Open questions (in `docs/questions.md`)

- **M1-1**: object tags in `at` conditions. Literal reading kept.
- **M1-2**: role holders perceive all of their storylet's events. This makes Marti always
  overhear `crew_chatter` and cancels the slice's open-window test. Spec kept; there are three
  options for you.
- **M1-3**: `chance:<n>` keys rolls by order in the tick. Literal reading kept.
- **M1-4**: no transition on the activation tick.
- **M1-5**: **performance for M2.** At about 130 µs per history-tick, M2's 100 ms recompute
  budget is roughly 80× away before merging. M2 will need a faster step, or a lower cap.
