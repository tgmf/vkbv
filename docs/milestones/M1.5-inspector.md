# M1.5 — Dev inspector (added by Tagir, 2026-11-21)

**Goal:** see what one history does, in the browser, before the wave exists. A developer tool,
not the game view: M5 still builds the real viewer (wave, ghosts, lantern, timeline).

## Build

1. A dev message pair in `src/bridge/protocol.ts`: `inspect { seed, stream, pins, tick }` →
   `inspected { view }`. The worker runs `runHistory` once per (seed, stream, pins), keeps it,
   and answers each tick with a small view: cats (position, place, activity, control, interrupt,
   gauge values), storylet states, facts, flags, closed edges, running effects, weather, the
   tick's events as text lines, and the end.
2. `src/content/data/pinsets.json`: the pin sets of `05` §5.1 in the spec's notation
   (`card@target@tick`, `!` marks a special), parsed and checked by the loader.
3. `?dev=1` page: an SVG map of places and edges with the cats as dots, a tick slider,
   play/pause, the two play speeds, ←/→ to step; side panels for this tick's events, the cats and
   the running storylets; seed, stream and pin-set controls. Text is developer-only and not
   translated.
4. The event formatting of `npm run sim` moves to `src/sim/trace.ts` so the CLI and the inspector
   print the same lines.

## Out of scope

Waves, observation, anything a player does, styling beyond legibility. In M8 the inspector moves
into the debug panel as its History tab.
