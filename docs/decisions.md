M1  All Chapter 1 schemas live in one file, `src/content/schemas/chapter.ts` (a section per data file), instead of twelve small files; shared language in `schemas/dsl.ts` — easier to read side by side.
M1  `Condition`, `PlaceSelector` and `Requirement` types are written out once next to their schema because `z.lazy` recursion cannot be inferred; TS checks the two agree.
M1  `load.ts` derives the lookups once (edge ids `a__b`, adjacency, each place's space, door-to-outdoor flag, object tags; records by id) and deep-freezes `Content`. Cross-checks are in `content/check.ts`.
M1  `src/content/chapter1.ts` imports the Chapter 1 JSON statically so the app, the worker and Node tools load the same set; `src/cli/files.ts` (Node only) reads other folders such as the tiny world. `src/cli` is type-checked by `tsconfig.node.json`.
M1  `step` takes either the list of decided branch outcomes (it throws an internal signal at the first undecided one and returns `branchPoint`) or a resolver function that samples as it goes; single-history mode uses the resolver, a test checks both agree.
M1  Path results are memoised in a `PathMemo` object owned by the caller and passed through `Ctx` (no module state); the same inputs give the same paths, so behaviour is unchanged (same hashes).
M1  `cloneState` copies what a step mutates and shares what it never changes (`initial`) or only replaces (flag entries, roles, pool matches); a test checks it equals a JSON round-trip and that stepping never changes its input.
M1  State has one field beyond `03` §5: `echoes`, the socialSpread re-emissions waiting for next tick. A terminal storylet state stays in `StoryletRun.state` (with `ended: true`), so `{ state: [s, terminal] }` holds after the end.
M1  Events beyond `03` §2's list, for traces and conditions: `fact` (a fact newly set), `activity` (an activity chosen, with its place), `interrupt`; `pinFired` carries `card` and `special`. Weather changes are global named events `rainStarted` / `rainStopped`.
M1  Hook voices compare the gauge value at the end of phase 3a with the step's input state, so a crossing caused by a pin in phase 1 still voices.
M1  A `blocked` edge counts as the activity ending: the cat decides again in phase 6 of the same tick (with the edge now known closed).
M1  A decaying mod gets `left = ceil(|add| / decayPerTick)`; `attracted` ends when its attract effect is gone; running effects count down in phase 1 including those created that tick.
M1  The start activity at tick 0 is chosen while building the initial state; its `activity` event is not part of any tick.
M1  The 03 §18 sweep over Chapter 1 (seeds 1–50 × streams 0–31) is split into eight test files by stream so Vitest runs them in parallel; `tests/invariants/check.ts` steps without keeping every state.
M1.5  The dev inspector talks to the worker through its own message pair (`inspect` / `inspected`), not `debugHistory`, because it needs a seed, a stream and a pin set; the worker keeps the last inspected history and answers each tick with a small `InspectView`. M8 folds it into the debug panel.
M1.5  The `05` §5.1 pin sets are data in `src/content/data/pinsets.json`, in the spec's notation (`!` marks a special), parsed by `parsePinSets` in `load.ts`; `npm run sim -- --pinset <name>` uses them too.
M1.5  The inspector's log shows the events of the ticks before the one viewed (they led to the state on the map); `events[t]` happen after `states[t]`.

Fogged cats are skipped in phases 3, 6 and 7 (they perceive only through the fog), and a detector that involves a fogged cat is left to the fog (Tagir approved both defaults, 2026-11-21). Keeping fogged cats out of live storylets is the lantern's job: it holds every storylet that a fogged cat could bind.

M2  Readers index (`03` §13.5): a reader's cats are, for an activity, the cats that list it; for a storylet, the cats its `{ cat }` and `{ roleTag }` roles name (`nearCat` roles name nobody); for a hook, the cats that have it; for a detector, the cats it involves; the anchor's requirement tree counts as one extra reader. "File order" for ties is the order quantities are first found: activities, storylets, hooks, detectors, primes, the anchor tree, then world conditions (fraysIf, edges, objects). `world.engineFacts` (the weather's facts) are never links. Chapter 1 links: `crewArrived`, `martiOut`.
M2  Place perception table (`03` §13.6): per cat, sense and weather, the range in mm between every pair of nodes, computed by the same `rangeBetween` as live perception; a sound's radius is applied at lookup. Tested equal to `perceives` on every pair.
M2  Fog chains (`03` §13.2): an activity's duration `[lo, hi]` ticks becomes the exact distribution of `ceil(d / stepTicks)` for `d` uniform in `[lo, hi]` (at least 1 step). Walking takes `ceil(pathTicks / stepTicks)` steps and a walking state makes no decision until it arrives (a live cat may decide at a node mid-route). Fogged cats plan as if every edge were open. Hook `when` conditions are read at the step's first tick.
M2  `nearCat` in the fog reads each other cat's most likely state, computed once per case and step. Within one step and case, chain states that differ only in how many steps are left share one decision result and one hook-condition result (a decision reads only whether any are left); results are unchanged by this cache.
M2  Band arithmetic: span = 1001 − floor, band(v) = trunc((v − floor) × bands / span), midpoint = floor + trunc((2b + 1) × span / (2 × bands)), width = trunc(span / bands). A move of more than one band moves whole bands, then the fraction.
M2  `scripts/fog-bench.ts` times one fog projection of the whole day (`FOG=minStatePpm,bands` overrides the knobs for measuring).

M2  Fog storylets (`03` §13.6) advance once per fog step: gates and triggers are read at the step's first tick, hazards compound over its ticks (P(none) = stay^K, fired mass shared by rate), choices happen when the step holds a decision tick, at most one transition per step. Roles bind on the fogged cats' most likely states (`nearCat` included).
M2  Effects of a fog-held storylet on a live cat are skipped: such a storylet reaches the lantern (§13.4, §15.1) before its effects can touch a live cat. A held gauge mod (`holdTicks`) on a fogged cat does not shift back yet; it comes with pins on fogged targets.
M2  Fog facts keep their sources: the masses entering one state of a once-storylet are disjoint and add; different sources combine as independent (1 − Π(1 − p)). Detectors raise their own source to their estimate.
M2  A link set by a storylet transition splits the case at the transition, exactly: in the new case the storylet is in that state and its onEnter runs at full mass; in the other the transition did not happen. (`03` §13.5 lets both cases inherit the same chains; without this, the "crew not arrived" case kept the crew working.) Other rises of a link split by the fact's probability, as written.
M2  Counters in the fog get one Bernoulli term per cat, counter and amount per step (a cat's states are exclusive); per-state terms truncated to nothing. (Since 2026-11-25 only with `fog.counterByChain` off; it is on by default, see below.)
M2  In the fog, a cat is the actor of an open choice (`03` §8.3) with P(its storylet is in that state); that share of its free states makes no free decision.
M2  The weather splits cases at fog-step granularity: a case that starts raining in a step is rain for that whole step; the start tick is tracked exactly for the stop hazard.
M2  Fog tests that run many Chapter 1 steps use the coarse measuring knobs (`ch1Coarse` in `tests/sim/helpers.ts`: minStatePpm 20 000, 2 bands) while M2-1 is open; the invariants they check do not depend on the knobs.

Decision cache key: two keys (`docs/questions.md` M2-6).
M2  Hysteresis (`03` §8.2): `lastKey` holds `hash32` of the decision key taken after the decision, so a cat's own switch is not a trigger. Triggers at once: arrival with an empty route, control handed back (storylet at full boredom, a `delay` ending, a goTo arriving), blocked, a built-in ending, an offer born; on decision ticks: a changed key or an ended interrupt. A goTo to the place the cat already stands ends at once. `activityFinished` is emitted on leaving any activity but `none`.
M2  The decision cache lives in a caller-owned `DecisionMemo` (like `PathMemo`), one per history or fog setup. Its key is the decision's exact inputs: gauges (band midpoints in the fog), boredom, every leaf's ppm (rounded to `fog.ppmQuantum` in the fog, in the decision too), offers with their scores, the cat's node, `knowsClosed`, and the places of `flag`/`nearCat` selectors (M2-6).
M2  Fog decisions: mass is marked as changed (transient, never stored) when a band of a gauge its decision reads moves (boredom always), its walk or interrupt ends, a goTo arrives, or storylet control returns (the share of a storylet's activity that tires past the top boredom band); all of a cat's mass decides when its condition vector (rounded leaves) changed since its last step. Band moves from perception at the end of a step trigger at the next change. Starts are memoised by place and activity within a step.
M2  The tiny test world's `work` now closes its gate after 10 units of work (`counter work lt 10`): without timers, that is what ends it, as `onFinish` → `workDone` → `shift.done` → `rite` → fray at tick 19 still requires.
M2  Fog decision inputs that do not depend on the deciding state, and hook conditions that read no gauge, are evaluated once per case and step; repeated states decide once per step; stand-ins and state keys are built once per step and shared by all cases; perception sums mass by place; quantities and split cases are copied only as deep as they change. `scripts/fog-hash.ts` checks results are unchanged (the fog's hash every hour).
M2  Fog counters are held in millionths of a unit (mean and variance), so a cat's fractional share of work is never truncated away; conditions read whole units (`counterOf`). Mixed cases' variance is the mean variance plus the spread of the means.
M2  `fogStep` takes the lantern's state (`live`): the fog reads live cats and the lantern's facts and weather from it. Placement and the lantern's events reaching the fog come with step 6. `scripts/fog-bench.ts --live` times Marti live with the others fogged, and the 08:00–12:00 re-run window of `07` §4.

—   2026-11-22 (Tagir) Banded gauges have a saturated top band (`fog.saturatedBandFrom`, 950): band edges floor + trunc(b × (950 − floor) / (n − 1)) for b < n, then 1 001; a band reads at trunc((lo + hi_exclusive − 1) / 2), so the top band reads 975. Band moves walk whole bands by each band's width, then the fraction. Decision-trigger keys use the same bands, so single histories changed: golden files updated with this as the reason.
M2  Role cats in the fog carry the storylet state that last directed them (`ChainState.sl`, `storylet.state`), M2-8: a storylet's cat-directed effect moves only the mass that belongs to its source state (not tagged with another state of that storylet), with the transition's probability given that state (`mass / P(source)`); a free choice keeps the tag; a cat is blocked as a choice actor by its own tag's state, or by the chance of the choice states where it has no tag. Without it the foreman's break-time work survived into `working` (he worked 23–41% of the morning instead of standing; the road ran ahead).

M2  The lint guardrail test runs with a 30 s limit: its first ESLint call builds the TypeScript program, about 1 s alone but past Vitest's 5 s default under the full suite's load. No assertion changed.
M2  Pins in the fog (`03` §13.6) are applied by `fogStep` only when there is no lantern (`live` null: projections, vetting, calibration). With a lantern the pins stay with the lantern's `step` until M2 step 6 splits them between lantern and fog. A step's pins fire at its start (before the chains move, like phase 1), in log order; their effects are born at the pin's tick.
M2  Pin validity per case: a card on a cat, a place card and a power are valid or not whatever the state; an object card is valid with P(visible). At its first step `fizzled = 1e6 − v`; every step `fired += (1e6 − fired) × v`, and the primitives act with that new share. Pins before the fog's first tick are the lantern's and are skipped.
M2  A card's `delay` in the fog is its own chain-state field `forced` (fog steps left), not `interrupt` as the comment in `03` §13.2 says: a delayed cat stands and performs (its `while` effects, boredom, a storylet choice's actor), an interrupted one does nothing, and one field cannot hold both at once. A delay on a walking state stands it at the end of its current edge. A live cat's `forcedLeft` becomes `forced` in its point mass.
M2  Fog running effects (`Quantities.effects`) carry P(they exist); one is in a step when `born < t + K` and `t < born + left − 1` (phase 1 counts it down from its first tick). The skeleton state holds those with P ≥ `fog.gateThresholdPpm` (docs/questions.md M2-10), so offers and `pin`/`power` conditions go through the shared code. An offer born this step marks the mass it reaches as changed; `attracted` ends when no attract effect is at its place.
M2  Temporary mods in the fog (`Quantities.mods`, per case, so splits and merges carry them): a decaying card mod shifts back over `ceil(ceil(|add| / decayPerTick) / K)` steps by `trunc(left / leftSteps)` each, the rest at its last step; a held mod (`holdWhileRunning`, a storylet's `holdTicks`) all at once when it ends; both on the same share of the chain they moved.
M2  socialSpread in the fog: a cat's newly heard share of an event with hops left is re-emitted at the next step from where its chain stands, with one hop less (`Quantities.echoes`).
M2  Contributor heaps (`03` §13.5) keyed `fact:`, `flag:`, `heard:<cat>:`; a source is `sl:<storylet>.<state>` (its roles' cats), `act:<activity>` (the cat), `pin:<id>`, `ev:<event>` (the emitter; for `factIfPerceivedBy` also the perceiver) or `det:<id>` (its estimate, kept as a maximum). The place is the effect's node, or where its cat most likely stands. Repeats combine as independent; the top `fog.contributors` by ppm are kept, ties by source.
M2  Pressure and `touchedBy` of fogged cats are not computed: only watched facts (M3) and placement (step 6) read them.
M2  Fog perception applies all four of `03` §4's always-perceived rules: global, addressed to the cat, emitted by it, and every event of a storylet in which it holds a role (`FogEvent.storylet`; the lantern's QUESTION M1-2 rule). A fact set by perceiving a once-storylet's event adds its disjoint shares, as that storylet's own facts do.
M2  Fog mass that a storylet effect hands back at once (a goTo to where the cat stands, a `stop`) decides in the step the effect lands (`finishStep`, through the same `decideMass` as `catStep`), as a live cat decides on the tick its control returns.
M2  `fogLeaf` reads `power` and `pin` leaves (`{ power, near: cat, m }`) as one cat's distance to the effect, not as the two-reference `near` condition.
M2  The backward pass lives in `src/sim/backward.ts` (a file not in `02` §2's list; `fog.ts` was already over 2 000 lines). Evidence is plain data: a fogged cat in (or not in) a list of chain states, a fact, a storylet state. Case weights are rescaled exactly (`floor(a × WAVE_TOTAL / total)` in two parts, so products stay below 2^53), the remainder to the first case, zero cases dropped. Smoothing waits for frame requests (step 9): nothing keeps earlier fog steps yet.
M2  `projectToEnd` steps a projection to the chapter's end (no lantern) and returns the raw fog, the anchor-conditioned one, the raw P(anchor) (strain, on a projection from the edge) and the fray (docs/questions.md M2-12). Strain in the debug panel and projections from the lantern edge with live cats as point masses come with steps 6 and 9.
M2  The lantern (`src/sim/lantern.ts`): `advance` = the lantern's `step` (reading the fog through `lanternReader`, the case mixture by weight), the fog step at each boundary (reading the lantern and perceiving its events), then the edge (release at boundaries, placement or negative evidence for each fogged cat, held storylets going live once all their roles are live). The lantern state adds `unseen` (ticks since a protagonist last saw each live cat) for release. Fog events drawn into the lantern wait for Gaze and imposed facts.
M2  In the lantern's step (`ctx.live` set) a condition reads what the lantern holds — its facts, flags, the storylets it runs, its share of counters — from its own state as it changes during the step; the reader gives only the fog's part (`fogLeaf`, `flagHolds`). The fog, stepping after the lantern's ticks, reads the lantern's state at that point (`caseCtx`).
M2  Pins with a lantern: a card on a fogged cat is the fog's (the lantern skips it); a card on a live cat is the lantern's; place, object and power pins are fired by the lantern, and the fog then applies the parts that act on fogged cats and held storylets (offers come from the lantern's running effects). A lantern-run storylet's `trigger` of a held storylet is not passed to the fog (no Chapter 1 storylet does it).
M2  A storylet with a `nearCat` role is held by the fog while any cat is fogged (it could bind any of them); it goes live only once bound and all its roles are live.
M2  Fogged cats walk as live ones: each edge costs its ticks plus one (the edge starts on the tick after the cat stands at its first node, `03` §6 phase 3e); stand-ins interpolate the same way. Found by the exactness test; it moves default fog results (calibration in the handoff).
M2  Fog key changes trigger only on a step that holds a decision tick (`03` §8.2): mass whose decision key changed (`k`) or that carries `due` (a change seen between decision ticks) decides then; arrival, handed-back control, offers and an ended delay decide at once (`d`). With `fog.stepTicks` = the decision interval (5) every step is a decision step and nothing changes.
M2  Fog events reach the lantern (`03` §13.4, §15.1): each case keeps its step's own events (`q.stepEvents`, tagged with the storylet state that emitted them). At each fog step boundary every event a followed protagonist would perceive (global, addressed to it, the role-holder rule of `03` §4 / QUESTION M1-2, or range and sense) is drawn once per name and place (`obs`, `event:<name>:<node>`) against its chance over the cases. A drawn one is case evidence and, unless it is a storylet's state event, an event of the lantern's next tick (perceived in phase 7); the rest is negative evidence. Who emitted it stays open.
M2  A fog-held storylet (or a lantern storylet the fog set going, e.g. by `trigger`) whose event a protagonist drew runs live from the state that emitted it, its other roles staying in the fog: the lantern's effects on fogged cats (`ctx.fogFx`) are applied to their chains at the next fog step; an emit from a fogged cat uses its most likely position.
M2  Where a detector runs follows the cats its clauses name (`namedCats`): with a lantern, one that names a fogged cat is the fog's, one that names none (weather, events, facts) the lantern's, which holds the world concretely; projections estimate both. (`detectorCats` keeps "no cat named = everyone" for perception.) Needed for Chapter 1's `boat_sails` (120 dry ticks after the rain), which the fog's estimate would collapse to the rain's stop.
M2  Links (Tagir, 2026-11-23): facts only storylets binding the followed protagonist set are lantern facts, never fog links; the first link slots go to counter races, one per counter (a fact set entering a state through an auto exit gated on that counter); at a race split each case's counter is conditioned on its side of the threshold with truncated-normal moments (the PHI table and its differences, integers only; a side under 0.1% pins the counter at the threshold).
M2  Calibration's reality draws its weather as the lantern does (`s0:branch` for the weather's branch points), so the run's odds and the reality share the world the run made concrete (07 §3).
M2  Watched facts (`03` §15.2): the summary also carries `self` (P's node, activity, interrupt) and `cats` (each cat P sees: node and activity), the parts a re-run compares. The fact of tick t is read after the step from t and its edge (`fact.tick = sim.tick − 1`), from that step's own events (`wave.tickEvents`); `digest` is `hash32` of the canonical JSON of `{tick, cat, summary}`. P perceives a storylet state it holds a role in or whose role cat it sees, a detector naming it, a cat it sees or no cat, and emitted events by `03` §4.
M2  Imposed facts (`03` §15.5) are compared at the edge of the step from their tick, before placement. A fogged cat a fact saw is forced only where the ordinary draws (`place:`/`pick:`) would not show it as watched, so an unedited re-run with its own watched facts is the same run; the forced state is drawn among the states with the watched node and activity, by mass (`obs`, `impose:<P>:<cat>`). The forced parts' probability for `reopenBelowPpm` is the product of their masses.
M2  Gaze (`03` §15.4) runs at the lantern edge after placement, so a cat a protagonist placed that tick is not gazed; the state a hit fixes is drawn among the circle's states by mass with purpose `gazepick:<pin>:<t>:<cat>` (the spec names only the first draw).
M2  Frames (`03` §16) are plain objects, one per tick (`Frame` in `types.ts`): per cat its ghosts `{ node, pos, activity, interrupt, p }` (a live cat one at 1 000 000; a fogged cat's grouped from its states over the cases, most likely first, the truncation remainder to the first, kept from the tick before when its chains and the case weights did not change); `happens` by emitted event name, `storylet:<id>.<state>` and `detector:<id>`; `rain`; `requirements` per top-level requirement item and `progress`. A frame's events are those of the step from its tick (as a watched fact reads them); a fog step's events go to the tick whose advance computed it. Compact arrays and transfers wait until the worker measures patch sizes (item 10).
M2  The re-run (`recompute.ts`) is a generator: it yields each tick's frame as it advances and returns the `Timeline` (request, checkpoints, edge wave, result), so the worker can batch patches and cancel a speculative preview. Each re-run gets a fresh decision cache (`03` §8.2: cleared when pins change).
M2  The edit tick is the earliest tick of a pin or watched fact that differs from the timeline replaced (0 for none or another seed; that timeline's edge when nothing differs). The re-run starts at the last checkpoint strictly before it, so the tick before the edit is replayed and can become the edge.
M2  Frontier limit (`04` §6, literally): tick t passes when its watched fact (the step from t) shows no main storylet outside `frontier.storylets`, `progress(t) ≤ story` and `t − reach ≤ pastTicks` (`reach` from tick 0, earlier ticks read from the kept frames); the edge is the tick before the first that fails (0 at tick 0). The last tick (fray, anchor's end, chapter's end) has no step, so only progress and pastTicks are checked there. (Superseded for the main-storylet rule by M3-2: the edge is the tick whose step shows the new story, see the M3 line below.)
M2  Re-run ends: `fray` at the lantern's fray tick (`wave.fray`; for `fraysIf` that is the tick of the step that set `deadAt`, one before the wave that holds it); `anchor` (tick `reachedAt`) runs `end.afterAnchorTicks` past it; `chapterEnd` only if the chapter's last tick comes with neither (the lantern frays there without the anchor, so in practice never); `limit` otherwise. `breaks` are the reopened facts with a non-empty `paidBy`; Gaze facts are not part of the request, so none of them break here.
M2  `stats` carry per tick cases, live cats and fog states, plus `localCauses` and strain; the re-run time is the worker's (`src/sim` reads no clock). Strain is computed only when the request asks (the debug panel is open): `projectFrom` puts every live cat in the fog as a point mass and fixes the lantern's facts, flags, counters and storylet states in every case, then projects to the end; the lantern's running effects are not carried over (an approximation).

M2  `fog.counterByChain` (on by default since 2026-11-25, `b081a50`; M2-8/M2-23): each chain entry carries `w`, what its mass has added to counters through activities' `while` effects (mean in thousandths, variance in units² × 1000); a step stamps every entry made from a source entry with its work plus this step's, chain transforms carry it, `normalise` and case merges mix it, and the case's counter moves by the change of each cat's work mixture instead of a Bernoulli term. M2  With `fog.counterByChain`, a race counter's storylet (the first whose auto exit races on it) also carries work by state (`FogStorylet.w`): each step the work of mass tagged with a state (`sl`) is credited per unit of the storylet's mass in that state; the work moves with the storylet's transitions and mixes on case merges.
